# Exploratory Testing

Exploratory Testing is an approach where learning, test design, and test execution occur simultaneously.

Instead of following predefined test cases, the tester actively explores the application to discover unexpected behaviors, usability issues, and hidden defects.

Exploratory Testing relies heavily on the tester's experience, curiosity, and critical thinking.

---

# Purpose

Discover defects that structured test cases may not detect.

It answers questions such as:

- What happens if I use the application in unexpected ways?
- Can I reproduce unusual user behavior?
- Are there hidden usability problems?

---

# Characteristics

- Flexible
- Unscripted
- Human-driven
- Experience-based
- Creative
- Adaptive

---

# Example

Testing a registration form.

Instead of following predefined steps, the tester tries:

- Extremely long names
- Emojis
- SQL injection attempts
- Rapid repeated clicks
- Browser refresh during submission
- Copy-paste unexpected characters

These scenarios often reveal defects that formal test cases miss.

---

# When Is Exploratory Testing Useful?

- New applications
- Poorly documented systems
- Time-limited projects
- High-risk features
- After completing scripted testing

---

# Advantages

- Finds unexpected defects.
- Improves product understanding.
- Encourages critical thinking.
- Detects usability issues.
- Complements automated testing.

---

# Limitations

- Difficult to reproduce without notes.
- Depends on tester experience.
- Limited repeatability.
- Harder to measure coverage.

---

# Exploratory vs Scripted Testing

| Exploratory | Scripted |
|--------------|----------|
| Flexible | Planned |
| Creative | Structured |
| Learns while testing | Follows predefined cases |
| High adaptability | High repeatability |

---

# Best Practices

- Define a testing objective.
- Take detailed notes.
- Record discovered defects.
- Use time-boxed sessions.
- Focus on high-risk areas.

---

# Session-Based Exploratory Testing

A common technique is to work in time-boxed sessions.

Example:

```
Mission:
Explore User Registration

Duration:
45 minutes

Focus:
Input Validation

Deliverables:

- Notes
- Defects
- Questions
- Improvement ideas
```

---

# Key Takeaways

- Exploratory Testing combines learning and execution.
- It complements scripted and automated testing.
- It uncovers unexpected defects.
- Skilled QA Engineers use Exploratory Testing to improve overall software quality.
